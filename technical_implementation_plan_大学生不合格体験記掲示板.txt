技術的実装段階計画書：大学生向けの不合格体験記掲示板

1. 目的
本書は、前提となる仕様書をもとに、実際のWebアプリケーションとして実装するための技術計画を定義したものです。
本サービスは、大学生向けの不合格体験記を投稿・閲覧・共感・改善点共有できる掲示板型アプリとして開発することを目的とします。

2. 開発方針
- 技術要件はシンプルかつ実装しやすい構成を採用する
- 初期開発ではMVP中心に構築し、徐々に機能を拡張する
- SQLiteを利用してローカル開発とデプロイの簡易化を図る
- フロントはHTML/CSS/JavaScript、バックエンドはPython Flaskを前提とする
- 投稿・一覧・詳細・コメント・いいね・管理機能を最優先で実装する

3. 技術スタック
3-1 フロントエンド
- HTML5
- CSS3
- JavaScript
- BootstrapまたはCSSのみの簡易UI

3-2 バックエンド
- Python 3.11以上
- Flask
- SQLite3

3-3 追加ライブラリ
- Werkzeug（Flask標準）
- Flask-Login（ログイン実装時）
- datetime, hashlib, os, re
- 画像保存時は Pillowまたは標準ファイル保存方式

3-4 開発環境
- VS Code
- SQLite Browserまたは sqlite3 CLI
- Git
- Python仮想環境

4. システム構成
- ユーザーがブラウザでアクセス
- FlaskアプリがHTTPリクエストを受ける
- SQLiteデータベースに投稿・ユーザー・コメントなどを保存
- 画像ファイルは uploads/ フォルダに保存
- テンプレートは templates/ に配置
- CSS/JSは static/ に配置

6. データベース設計
6-1 usersテーブル
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    nickname TEXT NOT NULL,
    email TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    university TEXT,
    department TEXT,
    grade TEXT,
    role TEXT DEFAULT 'user',
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

6-2 postsテーブル
CREATE TABLE posts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    title TEXT NOT NULL,
    content TEXT NOT NULL,
    category TEXT NOT NULL,
    school_year TEXT,
    department TEXT,
    failure_type TEXT,
    cause TEXT,
    reflection TEXT,
    improvement_habit TEXT,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    is_deleted INTEGER DEFAULT 0,
    FOREIGN KEY(user_id) REFERENCES users(id)
);

6-3 commentsテーブル
CREATE TABLE comments (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    post_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    content TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(post_id) REFERENCES posts(id),
    FOREIGN KEY(user_id) REFERENCES users(id)
);

6-4 likesテーブル
CREATE TABLE likes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    post_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(post_id, user_id),
    FOREIGN KEY(post_id) REFERENCES posts(id),
    FOREIGN KEY(user_id) REFERENCES users(id)
);

6-5 reportsテーブル
CREATE TABLE reports (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    post_id INTEGER,
    user_id INTEGER,
    reason TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    status TEXT DEFAULT 'pending'
);

6-6 tagsテーブル
CREATE TABLE tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL
);

6-7 post_tagsテーブル
CREATE TABLE post_tags (
    post_id INTEGER NOT NULL,
    tag_id INTEGER NOT NULL,
    PRIMARY KEY(post_id, tag_id),
    FOREIGN KEY(post_id) REFERENCES posts(id),
    FOREIGN KEY(tag_id) REFERENCES tags(id)
);

10. バリデーション方針
- タイトルは必須、長さ制限あり
- 本文は必須、最低文字数を設定
- メールアドレス形式チェック
- ニックネーム長さ制限
- 不適切な表現の検出（簡易的な禁止語リスト）
- 画像拡張子とサイズチェック

11. セキュリティ対策
- SQLインジェクション対策: sqlite3 paramを使用
- XSS対策: HTMLエスケープ
- CSRF対策: フォームトークンの導入
- パスワードハッシュ化: sha256またはwerkzeug.security.generate_password_hash
- 画像ファイルのパス制御
- 管理者ページのアクセス制限

16. リスクと対策
16-1 リスク: 投稿本文の改ざん
対策: バリデーション、HTMLエスケープ、管理者削除

16-2 リスク: 匿名投稿による荒らし
対策: 禁止語フィルタ、通報機能、管理者制御

16-3 リスク: 画像アップロードの脆弱性
対策: ファイル拡張子制限、保存先制限、サイズ制限

16-4 リスク: 画面が見づらい
対策: 余白確保、見出し整理、カード型レイアウト、モバイル優先設計

17. まとめ
本アプリの技術実装は、MVPを最小構成で着実に進めることで開発リスクを下げることができます。
最優先で実装すべきは、投稿・詳細・コメント・いいね・検索・基礎認証機能です。
また、大学生向けの安心感があるUIと、失敗談に対する共感を生みやすい設計を重視して実装することが重要です。

次の段階としては、
1. データベース作成SQLの完全版
2. Flaskの実装雛形
3. 各HTMLテンプレートの骨組み
4. 各機能のルーティング詳細
まで具体化して実装に進めます。
